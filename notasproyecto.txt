07/10 VICTOR: Lo que he hecho es básicamente crear las carpetas y la estructura básica del backend con SpringBoot. 
Para que os hagáis una idea de lo que es springboot es esto: 

Spring Boot va a ser la parte del proyecto que se encargue de toda la lógica del servidor. El frontend será lo que vea y utilice el usuario, pero Spring Boot será el encargado de recibir las peticiones, procesar la información, comunicarse con la base de datos y devolver los resultados.

Por ejemplo, cuando un jugador cree un personaje desde la aplicación, el frontend enviará una petición al backend. Spring Boot recibirá esa petición, comprobará los datos y podrá guardarlos en MySQL. Después devolverá una respuesta al frontend.

La comunicación quedaría más o menos así:

Frontend (React)
↓
REST API
↓
Spring Boot
↓
JPA
↓
MySQL

Y la estructura del SB es la siguiente: 

controller: recibirá las peticiones del frontend.

service: contendrá la lógica de negocio.

repository: se encargará de comunicarse con la base de datos mediante JPA.

entity: contendrá las clases que representan los datos de nuestra aplicación, como usuarios, personajes o partidas.

config: tendrá las configuraciones necesarias del backend.


22/20: Victor.

1. Sistema de lanzamiento de dados

He creado DadoController.java en el paquete controller. Este controlador implementa el endpoint GET /api/dados/{caras}, que recibe el número de caras del dado y genera un resultado aleatorio entre 1 y ese número, devolviéndolo en formato JSON.

Esta funcionalidad permite automatizar las tiradas de dados de las partidas de Dungeons & Dragons y que el frontend pueda solicitar resultados al backend.

2. DTO de participantes

He creado ParticipanteDTO.java en el paquete dto, utilizando un DTO (Data Transfer Object) para transportar los datos de cada participante. Contiene dos campos: nombre y tirada, que identifican al participante y su resultado de iniciativa.

Se utiliza un DTO porque solo necesitamos recibir y devolver estos datos, sin crear una entidad nueva ni almacenarlos en la base de datos.

3. Sistema de ordenación de iniciativa

He creado IniciativaController.java en el paquete controller, con el endpoint POST /api/iniciativa/ordenar. Este recibe una lista de participantes en formato JSON, los ordena de mayor a menor según su tirada y devuelve la lista ordenada.

Por ejemplo, si el Guerrero obtiene un 15, el Goblin un 20 y el Mago un 12, el resultado coloca primero al Goblin, después al Guerrero y finalmente al Mago.

Esta funcionalidad automatiza el orden de actuación durante los combates y facilita la gestión de los turnos.
